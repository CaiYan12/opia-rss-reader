# GPU 初始化与风格性能核查（2026-10-22）

当前开发运行时存在已证实的 GPU 初始化阻断，已做局部环境修复。蒸汽梦核式另有已测得的动画绘制瓶颈，临时原型验证了保留动效的优化可能。正式样式实现未修改，本记录属于 audit 阶段，不是实现规格或视觉验收。

用户体验确认（2026-10-22）：用户明确反馈当前本机体验有巨大提升。当前持续生效的改动是三个运行时 DLL 的完整性标签修复；网格合成层原型已清除、未写入正式 CSS。该反馈补充了本机主观体验证据，不替代显示 FPS / 掉帧率测量或发行包验收。

## 已确认的环境原因

分支 `feat/synthwave`，代码基线 `a589663`。Electron 43.4.1 / Chromium 150.0.7871.224；系统显卡为 NVIDIA GeForce RTX 4070 Laptop GPU（驱动 32.0.16.1714）和 Intel UHD Graphics。

仓库没有调用 `disableHardwareAcceleration()`，也没有强制 GPU 后端或显卡的设置。故障时窗口可以显示，但 `getGPUFeatureStatus()` 报告 `gpu_compositing`、`rasterization` 为 `disabled_software`，GL 为 disabled，`getGPUInfo('complete')` 拒绝并报告 GPU process 多次失败。

详细日志把失败位置收窄到 `gl::init::InitializeStaticGLBindingsOneOff failed`。`electron.exe` 已是 Medium 标签，但 ANGLE / D3D compiler DLL 仍继承 Low 标签。Windows 的 `NoLowMandatoryLabelImages` 策略可阻止加载 Low 标签模块，机制见 [Microsoft 文档](https://learn.microsoft.com/en-us/windows/win32/api/winnt/ns-winnt-process_mitigation_image_load_policy)。此处的归因以以下本机反向实验为依据，不仅依赖通用机制。

| 对照 | 唯一相关改动或条件 | 实际结果 |
|---|---|---|
| 原运行时、空白窗口 | 默认参数 | 软件合成，静态 GL 绑定失败 |
| 原运行时、空白窗口 | 增加 `--force_high_performance_gpu` | 仍失败 |
| 临时运行时副本 | 相同文件内容，副本未继承工作区 Low 标签 | RTX 4070、硬件合成启用 |
| 同一临时副本 | 仅将两个 ANGLE DLL 改为 Low | 复现软件合成回退 |
| 临时副本 | 全部 DLL 为 Low，逐步恢复 ANGLE 和编译器标签 | 仅恢复两个 ANGLE DLL 不足以修复；恢复三个下述文件为 Medium 后成功 |
| 原运行时 | 只将三个下述文件改为 Medium | RTX 4070、硬件合成启用 |
| 实际项目入口 | `npm run dev -- --remoteDebuggingPort 9338` | RTX 4070 / D3D11，GPU 合成、栅格化、WebGL 启用，GPU sandbox 为 true |

临时副本与原文件的 `electron.exe`、`libEGL.dll`、`libGLESv2.dll` SHA256 一致。显卡强制参数只用于失败对照，没有写入项目或用户环境。

## 已实施的局部环境修复

只对 `node_modules/electron/dist/` 下三个文件执行 `/setintegritylevel M`：

- `libEGL.dll`
- `libGLESv2.dll`
- `d3dcompiler_47.dll`

操作前保存各文件的安全描述和 SHA256，操作后核实三个文件内容和 DACL 均未变化。工作区目录 ACL、原 AppData 路径、显卡驱动、系统 GPU 偏好和 Chromium sandbox 均未调整。运行时文件被 Git 忽略，本轮可提交的变化只有诊断文档。

修复后实际应用的 GL renderer 为 `ANGLE (NVIDIA, NVIDIA GeForce RTX 4070 Laptop GPU (0x00002860) Direct3D11 vs_5_0 ps_5_0, D3D11-32.0.16.1714)`。

范围边界：此修复验证的是当前 `node_modules/electron/dist/` 开发运行时，尚未验证 portable / win-unpacked 发行文件。重装依赖或生成新文件后可能再次继承 Low 标签，需重新核查；不能据此承诺发布包也已修复。

## 滚动测量口径

原先软件合成记录保存在临时目录 `opia-synthwave-perf-jLPIRc`。本轮原始证据在 `%TEMP%/opia-gpu-audit-UYYscN/`，包含探针、每组 result.json 与 Chromium 日志、original-security-backup.json、repair-verification.json、actual-dev-gpu.json、hardware-perf-environment.json、cadence-comparison.json、各组回调时间和 trace。临时 profile 含本地缓存，仅作本机诊断，不应提交或公开。

性能测量使用真实 Electron 主进程 / preload / IPC / renderer，配置复制到临时 profile，不用 window.opia 内存桩。项目正常入口另做 GPU 状态验证。正常入口启动进行了真实订阅刷新，日志为 `[main] initial refresh, added=1`；性能阶段的风格和缩放切换仅写临时 profile。

- renderer viewport 1099 × 721 CSS px，devicePixelRatio 1.75；显示器报告 165Hz。
- 同一篇缓存文章含 32 个条目、34 个图像元素；synthwave 内容缩放为 1，scroller 1091 × 593 CSS px、scrollHeight 15976。
- CDP mouse gesture：从 scrollTop 0 向下 3000 CSS px，目标速度 600 px/s，约 5 秒。
- 每段开始和结束 document 均可见，`data-app-hidden` 均未设置，最终 scrollTop 为 3000。
- 下表是 requestAnimationFrame **回调频率**，不是显示 FPS。浏览器合成线程仍可能呈现主线程尚未更新的局部帧，不能由回调频率直接计算显示掉帧率。
- 含完整 trace 的硬件样本约 18.4Hz，无 trace 的样本可明显更高；采集开销显著，含 trace 与无 trace 的数据不能混合评价优化幅度。

## 蒸汽梦核式：优化可能已得到原型支持

以下均为恢复 RTX 4070 后、不录完整 trace 的样本：

| 状态 | rAF 回调频率 | 可作出的判断 |
|---|---:|---|
| 原样 | 14.9–48.9Hz，多段 | 本机仍有明显且波动的主动画更新压力 |
| 仅暂停透视网格动画 | 129.3、130.1Hz | 网格动画是可复现的主要影响因素 |
| 仅将模糊改为 12px | 16.6Hz，单段 | 未显示改善，不能据此主张降级或认定 12px 更差 |
| 保留网格运动的临时合成层原型 | 133.4Hz，单段 | 在本样本中可同时保留网格运动、18px 毛玻璃并改善回调频率 |
| 移除原型、恢复原样 | 15.5Hz | 改善随原型撤除而消失 |

现有网格在整个透视平面上动画 `background-position`，并声明 `will-change: background-position`。临时原型保留父层的 perspective / rotateX / mask / 地面底色与地平线，将周期网格纹理置于子伪元素，用 `transform: translateY()` 做相同周期的移动；computed 卡片模糊仍为 `blur(18px) saturate(1.15)`。这是对优化路径的验证，不是已证明逐像素等价的正式实现。

临时注入样式与原型已清除，项目源码、风格参数、视觉守卫均未修改。亮侧、不同缩放 / 视口、连续动效视觉、降低动态效果、窗口隐藏暂停、订阅页与 keep-alive 多标签的正式回归尚未进行。当前证据支持继续验证合成层位移动画，不能承诺所有页面都会达到该频率。

## 合成层改造后的同批次对照（#45）

#44 已把周期网格纹理移进 `.juya-scene-grid.juya-scene-grid-persp::after`，动画只动 `transform`。本节是落地后的边界回归结论，以及同批次「默认（网格动画在跑）」与「暂停」的对照。

**边界（先读）**：样本是 `scripts/perf-probe.mjs` 生成的**合成文章**（32 条目 / 34 图像），不是上文那篇 15976px 的缓存文章；数字来自**单机单批次**的 rAF 回调频率，不是显示 FPS，**不可跨批次、跨样本比较**。绝对 Hz 不设门槛，100Hz 只作参考（见 SPEC「Testing Decisions」）。

测量条件（`npm run perf:probe --mode light`）：

- 批次时间：2026-10-22 20:14:39–20:18:02（本地 UTC+8；报告 `createdAt` 12:14:39–12:18:01 UTC）
- GPU：NVIDIA GeForce RTX 4070 Laptop GPU；`npm run diagnose:gpu` 与每次运行的应用内状态均为 PASS，硬件合成 / 栅格化启用
- 显示器 165Hz；renderer 视口 1099 × 721 CSS px，DPR 1.75，uiZoom 1；每组空闲基线均实测 165Hz
- 手势：scrollTop 0 → 3000 CSS px、600 px/s；每段开始 / 结束 document 均 visible、`data-app-hidden` 未设置、窗口前置且聚焦
- 对照组：`--pause-grid` 只往探针自己的临时 profile 页面注入 `::after { animation: none !important }`，**产品 CSS 与构建产物未改**。实测纹理层 `animation-name` 默认组为 `jy-grid-scroll`、对照组为 `none`，不一致时报告直接判「样本不可比」。

**第一批（默认组先跑，A/B/A/B/A/B）**

| 顺序 | 组 | rAF 回调频率 | 中位间隔 | P95 间隔 | 最差间隔 | >33.34ms |
|---|---|---:|---:|---:|---:|---:|
| 1 | 默认（网格在跑） | 123.5Hz | 6.1ms | 12.3ms | 24.1ms | 0 |
| 2 | 对照（网格关断） | 76.9Hz | 12.1ms | 18.2ms | 36.4ms | 1 |
| 3 | 默认 | 72.9Hz | 12.2ms | 18.3ms | 36.5ms | 2 |
| 4 | 对照 | 135.9Hz | 6.1ms | 12.2ms | 24.3ms | 0 |
| 5 | 默认 | 72.0Hz | 12.2ms | 18.3ms | 36.4ms | 1 |
| 6 | 对照 | 141.5Hz | 6.1ms | 12.2ms | 18.1ms | 0 |

中位数：默认 72.9Hz / 对照 135.9Hz，**对照 / 默认（关 / 开）比值 1.86**。

**第二批（对照先跑，B/A/B/A/B/A，用于检查顺序偏差）**

| 顺序 | 组 | rAF 回调频率 | 中位间隔 | P95 间隔 | 最差间隔 | >33.34ms |
|---|---|---:|---:|---:|---:|---:|
| 1 | 对照 | 75.5Hz | 12.1ms | 18.3ms | 24.3ms | 0 |
| 2 | 默认 | 86.6Hz | 12.1ms | 18.2ms | 42.5ms | 1 |
| 3 | 对照 | 101.5Hz | 11.8ms | 18.1ms | 30.0ms | 0 |
| 4 | 默认 | 97.9Hz | 12.0ms | 18.2ms | 30.3ms | 0 |
| 5 | 对照 | 111.6Hz | 6.1ms | 18.1ms | 30.2ms | 0 |
| 6 | 默认 | 126.4Hz | 6.1ms | 12.2ms | 24.3ms | 0 |

中位数：默认 97.9Hz / 对照 101.5Hz，**对照 / 默认（关 / 开）比值 1.04**。

**结论**

- 两批比值**同向**（1.86 与 1.04，均 >1，即暂停组更快），但幅度相差很大；且批内样本随时间单调变快（第二批 75.5 → 111.6 / 86.6 → 126.4），与组别无关。也就是说本样本上的组间差异**小于批内漂移**，不能用它归因于网格动画开关。
- 本节的对照是「新版内部：网格动 vs 不动」，**不是**旧实现 vs 新实现，不能用来量化 #44 带来的收益；旧/新 A/B 需要另做（同一探针须先能识别两种实现）。
- 因此本轮**不主张**合成层改造在这个口径下带来可测收益，也**不主张**没有收益；能确定的是：改造没有可复现的负面证据，且 §「蒸汽梦核式」那次「暂停网格 → 129.3 / 130.1Hz」是缓存文章上的单对比较，与本节的合成样本不可混档。
- 要把开关差值从漂移里分出来，需要更长的采样窗口、批内预热丢弃或交错重复（每组 ≥10 段）——属后续工作，不在 #45 范围。
- 绝对 Hz 不进 `verify` / CI / 退出码；100Hz 只作参考线，本次 12 段样本中 6 段低于它、6 段高于它（72.0–141.5Hz），不构成判据。

**确定性回归（同批次代码，Playwright）**

- 四组合（阅读页 / 订阅页 × 亮 / 暗）：网格可见、底边在滚动口可视区内、纹理层两次采样 `translateY` 不同（动画真的在跑）、纹理层上下缺口 ≤0（不露底）、左右 0 内缩且平面居中于滚动口（不错位）。
- `uiZoom` 1.2（亮 / 暗）：同一组不变量在两个动画相位都成立。注意此时场景层按 1.2 倍渲染，投影后的网格底边会落到视口下沿之外（实测 plane.bottom 1046.8 vs 滚动口 bottom 900），属缩放语义而非露底——可见区域仍被纹理层盖满。
- ≤520px 窄窗（520 / 480，亮 / 暗）：底边在视口内、无露底、无横向溢出。
- `prefers-reduced-motion`（亮 / 暗）：纹理层 `animation-name` 为 `none`，且 450ms 内 `translateY` 不变（计算样式断言，不只是静态守卫）。
- `[data-app-hidden]`（亮 / 暗）：`animation-play-state` 由 `running` 变 `paused`，移除标记后回到 `running`。
- 多标签 keep-alive：订阅页 + 阅读页同时存活时各只有 1 个网格平面；切走再切回后 `::after` 仍在动，平面数不增加（无叠层）。

## 暗夜精修式：仍需进一步定位

按用户原有 `uiZoom=1.2` 测量同篇文章，原样三段为 55.3、104.9、125.3Hz；暂停全部动画单段为 145.9Hz，单独暂停 dust 为 106.1Hz。结果有明显冷暖 / 时间波动，单独暂停 dust 未稳定优于原样，因此不能把暗夜精修式的剩余卡顿归因为 dust 或任一特效，也不能借此宣布该风格已完成性能验收。

## 本机 GPU 自检入口

2026-10-22 按用户选择增加独立自检命令，用法和退出码的唯一入口见 README「本机 GPU 自检」。实现由 `scripts/gpu-diagnostics.mjs` 调用真实 Electron 隐藏探针和 Windows 只读标签查询组成，报告保存在 Git 忽略的 `out/gpu-diagnostics/`，不接入 `verify` / CI，不自动修改标签或显卡设置。

探针只在观察到 `gpu-info-update` 后采信硬件加速状态，报告活动显卡、合成 / 栅格化、版本与初始化错误；缺失信息、超时不算通过。Windows 标签读取显式查询 `LABEL_SECURITY_INFORMATION`，不依赖可能遗漏 mandatory label 的 `Get-Acl`，也不解析本地化的 `icacls` 显示文字。

本机运行已验证：当前运行时 PASS；临时副本 Low 标签回归返回 FAIL / exit 1，未自动修复；受控挂起进程返回 INCOMPLETE / exit 2 且清理完成；中文 / 空格报告路径可用。新增 14 个命令与判定单测；最终 `npm run verify` exit 0（533 单测、128 E2E、对比度审计、5 张归档逐字节一致）。命令检测独立运行时的初始化健康，不取代实际应用、发行包或显示 FPS 的验收。
