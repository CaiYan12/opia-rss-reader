# 验证指南

测试、截图、原生验收或编写新探针前，读取命中的小节。可执行命令以根目录 `package.json`、[README](../../README.md) 和现有脚本为准；不要在此另维护一份测试数量或 CI 状态。

## 选择检查

- 产品代码改变后，按项目标准运行 `npm run verify`，局部迭代先用相关单测／E2E。实现子票的定向检查与收口票的全量检查由控制者分工，避免代理各跑一遍全量。
- 纯文档导航或措辞变化，确认没有改变产品、测试／夹具、构建配置及环境后，只运行文档引用检查与会读取这些文档的现有守卫。不要为了文档变更启动应用。
- 主进程行为变化需检查真实运行日志。浏览器 `window.opia` 桩只证明渲染层；真实进程与资料隔离见下文。
- 影响渲染的 CSS 取值改变后，先运行 `scripts/nocturne-visual-walkthrough.mjs` 写入模式，再运行归档验证；只有 `--verify` 会比对而不会更新文件。无关风格的归档发生变化时先查原因，不直接接受新基线。
- 本地 `verify` 包含机器相关归档字节比对，CI 的 `verify:ci` 按 workflow 跳过它；两者证明范围分别报告。既有 nocturne 归档不能证明所有风格逐字节不变。

## 候选与证据复用

每份记录至少包含：候选 commit 或工作区文件指纹、测试／夹具、命令与配置、必要环境信息、实际退出码、输出及截图位置。通过记录可按同一验证输入复用。

- 源码、测试／夹具、运行配置和相关环境均未变时，复用已有通过记录；仅文档提交或合并不会自动使其失效。
- 任一相关输入改变后，明确受影响范围，并按上述标准补跑必要检查。新增测试也属于验证输入变化，不能只比较 `src` 树哈希。
- SHA、测试数量和退出码从实际输出生成或核对；区分“此前实跑”“本次重跑”“代理报告”与“独立复核”，不以另一候选的结果替代当前证明。
- 原始失败、脚本修正和补测分开保存。采集误报可以解释并补证，不能把原始 exit 1 改写成当时 exit 0；数字写错时明确标记“这是初版写错的地方”。

## 新增探针与部分失败

1. 先查现有 `tests/e2e/`、`scripts/`、[UI 参考](ui-reference.md)中的测试基建及相应风格施工记录，复用已有夹具、计算口径和入口。
2. 先用最小样本跑通完整生命周期，再扩大矩阵。做前后对照时，先各跑一个旧／新版样本，确认 selector 与交互路径兼容两端，包含正常收尾。
3. 每个样本完成即写入数据、截图元信息和进度；完整记录不能只存在内存。异常处理先保存已取得的证据，清理失败也应单独记录。
4. 只有部分采集失败时保留有效成果，补测失败部分。若必需信息未保存，先修通局部采集，再补最小缺失范围，不从截图猜测未记录的几何值。
5. 先区分产品失败、环境失败和探针假设错误。旧版预期行为属于 before 观察；新版验收断言单独统计。图片方向属性不等同实际列布局，版式使用计算样式与矩形验证。

临时忽略脚本不自动属于 `verify` 的检查输入。语法检查不等于未定义符号检查；需要机械约束时使用相应静态检查或把可复用逻辑纳入现有检查链路，不用更多 AGENTS 条款代替它，也不声称未配置的检查已接通。

## 截图、焦点与几何

- 固定样本、viewport、DPR、内容缩放、字体环境、滚动位置、动态偏好及默认／hover／focus 状态；等待所需字体、图片和入场过渡就绪后采样。
- 焦点与颜色在过渡结束或连续采样稳定后判断。记录 `:focus-visible`、活动元素及实际颜色，不把过渡起始的透明环当作最终效果。
- 实际使用字体以平台字形信息为证；`font-family` 声明和字体可用性检查不能替代实际字形字体。
- `getBoundingClientRect()`、布局尺寸、窗口 bounds、viewport 和设备像素分别标明口径。CSS zoom 与 DPR 下不要直接比较不同单位，也不要为了整数假设调整产品或放宽验收。
- 坏链可验证内容降级，不可当作图片比例样本。真实在线内容与确定性离线样本分别记录，避免在线变化污染前后比较。

## 真实 Electron

默认使用隐藏窗口和后台连接，保护用户前台。需要显示、聚焦、OS 键鼠操作或停止用户进程时，先说明必要性并取得明确授权；占用处理见 [Windows 参考](windows-runtime.md)。

- 在真实 main 初始化及 ready 前配置独立的 userData、sessionData 和 crashDumps，确保目录存在。保留真实 main/preload/IPC 链路，不用浏览器桩替代原生证明。
- 日志应从初始化前开始捕获并及时落盘；若在 launch 返回后才订阅 stdout，先确认是否漏掉了早期刷新日志。测试 bootstrap 的采集逻辑与产品代码分开。
- 记录实际解析的资料路径，必要时对日常资料目录作只读前后比较；不公开真实配置、订阅资料或密钥。结束时只关闭本次启动的进程与服务。
- 分别记录源码配置、启动参数和运行时状态。主进程未额外传 `--no-sandbox` 不能证明 renderer sandbox 已启用，也不构成修改既有安全配置的理由。
- 隐藏窗口的 DOM 焦点不是 OS 前台焦点；截图、rAF 回调、trace 计数不是物理显示 FPS。不能覆盖的项目如实列出，不靠启动前台补齐未授权项目。

## 报告完成条件

必需检查已实际结束，退出码与候选输入已保存，原始失败与补证可区分，前台／资料保护和未测边界明确后，才将该验证阶段标为完成。
