# nocturne-dark（暗夜精修式·暗侧）优化需求对齐

> **状态**：需求已对齐，**尚未实施**。本文是唯一需求来源，不含代码实现。
> **对齐日期**：2026-10-12 · **对齐方式**：grilling-session（4 轮 16 问）
> **范围**：**仅 `nocturne-dark` 变体**。`nocturne-light` 不在本轮范围。
> **基线**：commit `b8be42c` · tsc 0 错误 · vitest 319/319

---

## 0. 为什么做这件事

用户判断：当前暗夜精修式**"完全是纯暗色主题，完全没有精修的感觉"**——没有橘鸦定制风格特有的自写图文排版、没有背景、neon 标题样式不足、没有主文本 context window。

经代码与实测核实，该判断成立且比预期更彻底。`juya.css` 中 `.jynoct` 共 15 条规则，**没有一条**触及 `.juya-section` / `.juya-lead` / `.juya-overview` / `.juya-links`：

| 风格 | 栏目 h2 | 导语 | 概览 | 链接 |
|---|---|---|---|---|
| pop | 5 | 2 | 0 | 1 |
| folio | 2 | 0 | **4** | **3** |
| y2k | 2 | 0 | 0 | 2 |
| editorial | 2 | 1 | 0 | 0 |
| wabi | 2 | 1 | 0 | 0 |
| dreamcore | 0 | 1 | 0 | 0 |
| **nocturne** | **0** | **0** | **0** | **0** |

模板侧 `nocturne.tsx`（46 行）是七风格里最朴素的：`EntrySplit` + 纯文字 h2，**未挂 `Scene` 场景层**（dreamcore 挂 `sun grid="persp"`、y2k 暗侧挂星空+地平网格）。

叠加字体问题：nocturne 声明的 `Inter, 'SF Pro Display', 'Segoe UI', 'Noto Sans SC'` 中，**Inter 与 SF Pro 本机未安装**，实测中文全落 Noto Sans SC、拉丁落 Segoe UI——**与全应用 UI 字体完全一致**，风格识别度归零。七风格里六个用衬线标题（Noto Serif SC），nocturne 是唯一全无衬线者，但"唯一"因落回通用字体而变成"无差别"。

## 1. 定位（决策 1）

**风格定位 = 氛围 + 排版双轨。** 氛围是背景，正文是主角。

`nocturne` 在八风格中的专属生态位是**"深夜精修室"**——这是其他风格都没占的位置：

- dreamcore = 赛博幻觉（synthwave 太阳 + 透视霓虹网格）
- y2k = 千禧网页（铬面刊头 + 星空地平网格）
- folio = 信纸精读（横格 + 朱丝栏 + 印章）
- pop = 波普艺术（描边硬阴影 + 多色拼贴刊头）
- editorial / wabi / newsprint90s = 衬线杂志与报刊
- **nocturne = 唯一「纯无衬线 + 非具象氛围 + 排版纪律」**

**排除项**：不做强具象场景层（会与 dreamcore / y2k 撞车）；不做纯工具理性派（那正是"没风格"的现状）。

### 2.2 决策

三档无衬线字体分工，**零衬线**：

| 用途 | 字体栈 | 理由 |
|---|---|---|
| 标题（h1/h2/h3） | `'DengXian', 'Noto Sans SC', 'Segoe UI', sans-serif` | 等线现代、字形干净、有重量；八风格中无人占用 |
| 正文 | `'Noto Sans SC', 'Segoe UI', sans-serif` | 不抢镜；正文对比度当前 11.50:1 极健康，不动 |
| 元信息/序号 | `'JetBrains Mono', 'Noto Sans SC', monospace` | 已有语言，保持 |

**与 C 定位同构**：氛围（dust/nebula）+ 排版（等线标题 + 三档字族）。与六风格无一撞脸。

## 3. 背景层（决策 3、4）

### 3.1 nebula：静态渐层雾

**决策：三层 alpha 减半，且避开正文列中心区。**

| 层 | 全强度 | **采用** |
|---|---|---|
| 紫蓝 `rgba(110,123,255,·)` | 0.14 | **0.07** |
| 青蓝 `rgba(90,160,255,·)` | 0.08 | **0.04** |
| 品红 `rgba(200,90,180,·)` | 0.05 | **0.025** |

**实测依据**：三层全强度叠加会把背景从 `#0a0a0c` 提亮到 `#262845`，**muted 文本对比度从 5.84:1 跌到 4.21:1 —— 跌破 AA 4.5**。这是暗色加氛围层的典型陷阱（审计已在 y2k 记录过同类问题）。减半后底色约 `#1a1b2e`，muted 约 5.0:1，仍过 AA。

**额外约束**：nebula 须避开正文列中心区，只在页面顶部与两侧边缘出现。

### 3.2 dust：尘埃级微粒

新 Scene 预设。一两千个微粒点、极低透明度、极慢漂浮或呼吸。存在感极低（不抢正文），但页面不再是纯色平面。必须走 `prefers-reduced-motion` 降级。

### 3.3 实现路径

**给 `Scene` 组件新增 `dust` / `nebula` 预设**（用户明确选择，不走纯 CSS token 路径）。约束：

- Scene 是**共享层**组件，新预设必须做到其他风格零影响
- 动画只挂 `.juya-scene-*` 子层；`.juya-root` 永无 animation（AGENTS.md 硬约束，reduced-motion 断言依赖此结构保证）
- **已知根因**：`.juya-scene` 的 `height: 100vh` 未扣应用 chrome 高度 **128px**。y2k 是段内缓解（`bottom: 136px`）。nocturne 须同样处理，否则底部装饰恒在视口外

## 4. 刊头 neon 标题（决策 5、6）

### 4.1 现状与陷阱

当前：`.jynoct .juya-masthead h1` 用 `linear-gradient(180deg,#ffffff,#b9bcc7)` + `background-clip:text`，实测读作**"银灰"而非 neon**。

**硬约束（y2k 已踩坑并记入 AGENTS.md）**：辉光**只能用 `filter: drop-shadow`，禁用 `text-shadow`**——`text-shadow` 在 `background-clip:text` 下会盖住渐变填充（Chromium 绘制顺序）。

### 4.2 决策

**微光 + 极慢呼吸**，色相沿用 `--jy-accent: #6e7bff`（零新色，与现有 token 同源）：

```
辉光：drop-shadow(0 0 18px rgba(110,123,255,.28))
    + drop-shadow(0 0 40px rgba(110,123,255,.12))   /* 远光层 */
呼吸：9s 周期，alternate 方向，强度在 .22 ↔ .32 摆动
降级：prefers-reduced-motion: reduce 下完全取消动画，保留静态辉光
```

**排除**：双色霓虹（青+品红）——会向 dreamcore 的 synthwave 霓虹语义靠拢，且侵蚀"克制微光"定位。

## 5. 正文阅读窗（决策 7）

**收窄列 + 两侧渐隐遮罩。**

- 正文区固定最大宽（约 **680–720px**）+ 居中，两侧留黑
- 左右边缘各加 **20–30px** 渐变遮罩，内容从黑里淡出（像代码块/播放器）
- 渐隐深度：**两端渐隐到 alpha 0.3**

**实测依据**（遮罩色 = bg 叠在正文上）：

| 遮罩 alpha | 正文对比度 | 判定 |
|---|---|---|
| 0.2 | 7.59:1 | 安全但存在感弱 |
| **0.3** | **5.97:1** | **采用**，安全余量充足且窗口感明确 |
| 0.4 | 4.63:1 | 接近 AA 底线 |

**排除**：发丝边框窗口——与"去卡片化"既定决策冲突（folio 已定案"透明/无边框直接写在纸上"）。

**当前状态（2026-10-12 实施前侦查校正）**：~~`.juya-issue` 无 `max-width`，靠 `.juya-feed` 的 760px 撑。~~
实际 `juya.css` 基层 `.juya-issue { max-width: 760px; margin: 0 auto; padding: 32px 24px 64px }`（内容盒 712px），`.juya-feed` 同为 760px（grid 预设 1120px）。**故收窄必须写成风格作用域覆写**（`[data-juya-variant='nocturne-dark'].jynoct .juya-issue`），改基层会同时波及其余 7 风格与订阅页；既有先例为 editorial 的 `.jyedit .juya-issue { max-width: 860px }`。**决策值（680–720px、20–30px 遮罩、alpha 0.3）不变。**

## 7. 签名件（决策 9、10）

### 7.1 栏目 h2：发丝分隔线

```css
.jynoct .juya-section > h2 {
  padding-bottom: 8px;
  border-bottom: 1px solid <栏目线>;
}
```

**栏目线 alpha 需单独提到约 0.22**。依据：当前全局 `--jy-border: rgba(255,255,255,0.08)` 合成后 `#1e1e1f` vs `#0a0a0c` = **1.19:1**（亮侧 1.24:1），几乎不可见。

> **2026-10-12 实施期算术校正**：原文写「达 3:1 需 alpha ≈ 0.22（暗）/ 0.28（亮）」，**该推导有误**。#6 实测（并从规则抠真值 + 自写 alpha 合成复算）：`rgba(255,255,255,0.22)` 叠在 `--jy-bg #0a0a0c` 上合成 **#404041**，对比度 **1.91:1**，不是 3:1；真要达 3:1 需 alpha **≈0.34**（合成 #5d5d5d ⇒ 3.01:1）。
> **处置**：按**明写并锁定的决策值 0.22 落地**（handoff 明确把「栏目线 alpha 0.22」列为不得漂移的决策值），1.91:1 已比全局 0.08 的 1.19:1 提升 **1.61×**、达到「可见」的目的；且栏目线是**装饰性分隔件**、不承载「理解内容所必需的图形对象」语义，非文本 UI 的 3:1 门槛不严格适用。
> 副作用已记录：`--jy-lead-bg` 由 0.04 提到 0.09，#6 说明该 token 同时被 `.jynoct .juya-entry:hover` 消费，故条目 hover 微亮同步增强 —— **有意保留**，因为该 token 是导语底色的**单一真源**（#9 的叠加态对比度实算要按 token 取值，若导语真实底色改用字面 rgba 而 token 仍写 0.04，实算会算错）。是否把栏目线提到 0.34 以真正达 3:1，留待用户裁决（会同时撞红 #6 守卫的 1.91±0.02 与 1.61× 两条断言，属预期）。

**只对栏目线提 alpha**，条目分隔线保持现状（提了会与"克制"冲突）。

**排除**：等宽序号前缀、两者叠加。

### 7.2 概览目录：发丝线 + 序号发光

当前 `.juya-overview` 零覆盖，是纯文字列表。改为：

- 序号（`.juya-index`，已是等宽灰色 `#` 小字）→ **用 accent 紫蓝发光**
- 条目间加**极淡发丝线**
- hover：整行背景微亮 + 下划线（底层已有 hover 下划线，只需加背景）

零新增色彩。

**排除**：终端/代码块样式——与"克制微光"定位有张力，会抢正文注意力。

## 8. 图文并排（决策 11）

**右列限 2 张，其余回流到正文下方通栏。**

**现状问题**（实测）：`EntrySplit` 中正文只渲染 `Paragraphs`（扁平投影，忽略 `parseJuyaIssue` 的 `blocks` 交错块），全部图片进右列 `ImageGrid mode="plate"` 堆叠；`LinksBlock` 是 `.juya-entry-row` 的**兄弟节点**，落在 `max(body, figure)` 之下。实测 420px 下 body 高 **152.9px** / figure 高 **429.3px** → **约 270px 空洞**。

**决策**：保留"图恒在右不交替"的纪律签名（这是风格签名件），但右列最多 2 张，第 3 张及以后回流到正文下方通栏。空洞从约 270px 降到约 100px 内。

**排除**：
- folio 的 `blocks` 交错——会失去纪律签名，且需改模板
- 链接移进正文列尾部——改共享层 `parts.tsx`，波及 y2k/editorial

## 10. 实施时的验收红线

1. **`npx tsc --noEmit` 零错误** + `npm test`（基线 319，不得回归）+ Playwright E2E（基线 86）
2. **不得使用 `text-shadow`** 做 h1 辉光（`background-clip:text` 陷阱）
3. **`.juya-root` 永无 animation**；动画只挂 `.juya-scene-*` 子层
4. **`prefers-reduced-motion: reduce` 下所有动效完全降级**
5. **Scene 新预设对其他五风格零影响**（改共享层组件，须逐一回归）
6. **`.juya-scene` 128px chrome 高度扣减**须处理
7. **nebula 叠加后 muted 对比度 ≥ 4.5:1**（正文文字 ≥ 4.5:1，非文本 UI ≥ 3:1）
8. **CDP `CSS.getPlatformFontsForNode` 取证**确认等线标题真实落地（`document.fonts.check` 对未装字体返回 `true`，是误报，不可作证据）
9. **每条构成色硬编码必带注释**，注明取色来源与对变体 bg 的 WCAG 对比度（AGENTS.md 惯例）
10. 变体专属覆盖必须写复合形式 `[data-juya-variant='nocturne-dark'].jynoct …`，带空格的后代形式永不匹配

## 12. 2026-10-31 补记：星尘夜空（封版例外）

> 本节是对 2026-10-12 对齐稿的**追加**，不改写 §1–§11 的历史决策；当前实现以本节、源码与归档为准。

**触发**：朋友反馈「暗夜精修式的暗色模式下，背景星辰不明显、且背景为纯黑，不符合设计直觉」；用户要求修改并逐轮确认。

**决策（Q1–Q9）**：两页都改；做星尘（不同大小／亮度／位置／间距，左上→右下密度递减）；底色 + 全页雾取更激进档；只动 `nocturne-dark`；正文列后允许亮星（Q5 B）；订阅卡半透明并追加毛玻璃（Q6 B，随后明确「卡片背景可以用毛玻璃模糊」）；亮星 11s/14s 错相慢闪；深靛蓝黑；右下保留稀星（明显档）。视觉候选已获用户认可（2026-10-31）。

**新取值**：

- `--jy-bg #0e0c18`；`--jy-muted #9a9ba6`；`--jy-lead-text #adb0b8`（未改）；顶部中央洗光删除。
- nebula：n1 `145%×125% at 0% 0%` rgba(110,123,255,0.105) / n2 `85%×95% at 100% 0%` rgba(90,160,255,0.05) / n3 `75%×80% at 0% calc(100% - 136px)` rgba(200,90,180,0.03)；允许重叠。窄窗单顶带 α0.08。
- 星尘：dust 覆写十层（46/55/70/83/104/122/157/175/194/258，点数 1461 @1280×800）+ 135° 密度 mask；亮星两层（640–1490px tile，11s/14s）。
- 订阅卡：`rgba(20,19,28,0.68)` + `backdrop-filter: blur(18px) saturate(125%)`。
